# Спецификация: самовосстановление лимитов и честный возраст цифр в Agent Control Bar

## Задача
Я смотрю на панель и вижу «5 HOURS 0%», «7 DAYS 30%», «Limits · 28d ago», хотя пять сессий работают прямо сейчас. Цифры не обновляются уже сутки, и приложение ни словом не говорит почему. Причины оказались две: терминальный Claude Code вышел из аккаунта, и опрос лимитов молча получает «токена нет»; после переименования приложения в «Agent Control Bar» путь к обёртке статусной строки в `settings.json` умер, и второй источник цифр тоже пропал. Чинить это руками на одной машине бессмысленно: у каждого пользователя после обновления будет то же самое.

## Решение
Приложение само следит за своей настройкой и само говорит, что не так:
- при каждом запуске оно находит свою мёртвую обёртку статусной строки и перепривязывает её на живой файл, не трогая чужие настройки; статусная строка в терминале снова рисует лимиты;
- когда опрос лимитов не может получить цифры, панель показывает причину («Claude Code не залогинен», «опрос не удался») и возраст последних цифр, а не делает вид, что всё свежее; один раз за запуск приходит уведомление macOS;
- кнопка в панели открывает Terminal с командой входа — вводить команду руками не нужно;
- подпись возраста честная: по каждому провайдеру своя, а у Codex она считается по живому пулу, а не по давно умершему резервному.
«Автоулучшение» из брифа здесь понимается как две вещи: приложение само чинит свою настройку и само сообщает, что мешает ему работать. Сам вход в аккаунт автоматизировать нельзя: он идёт через браузер и подтверждается человеком, поэтому приложение доводит до него одной кнопкой.
Список остальных найденных точек улучшения — в конце, с пометкой, что из этого сделано.

## Решения по реализации
- **Новая команда бэкенда `statusline --heal`** в `scripts/mcpbar.py`, функция `statusline_heal()`. Почему там: только эти функции читают и пишут `statusLine`, там же лок, бэкап и отпечаток файла. Правило: чинить только когда `statusline_ours(current)` истинно **и** ни одно слово команды с базовым именем `statusline.sh` не указывает на существующий файл. Новый путь — `find_statusline_wrapper()` рядом с работающим бэкендом: в канале плагина это `hooks/statusline.sh` плагина, в DMG-канале — `Contents/Resources/statusline.sh`.
- **Вызов починки из Swift при запуске** — `runQuietCommand(.statuslineHeal)` сразу после `checkHooks()` в `StatusController.init` (`main.swift`). Почему не `install.js`: Node-хук не знает про statusLine, а правило архитектуры держит `statusLine` в одном месте.
- **Файл состояния опроса `~/.claude/control-bar/limits-status.json`**, писатель — только `fetch_limits()` в `mcpbar.py` (атомарно, 0600). Почему отдельный файл, а не поле в `limits.json`: у `limits.json` два писателя с согласованным форматом и тест паритета; состояние опроса — факт об одном из них. Код выхода остаётся 0: приложение читает файлы, не stdout.
- **Чтение в Swift** — `loadLimitsStatus()` в `StatePolling.swift` с mtime-гейтом (как `loadLimits`), поле `limitsStatus: LimitsStatus?` в `main.swift`. Модель `Sources/Model/LimitsStatus.swift`: `struct LimitsStatus` (`state: String`, `ts: Double`, `detail: String`, `init?(json:)`) и правило `LimitsStatus.notice(oauthLimits:figuresTs:now:) -> LimitsNotice?` (`title`, `hint`, `offerSignIn: Bool`). Статусы — строки, не enum (правило проекта).
- **Панель**: снимок `PanelSnapshot` получает `limitsNotice: PanelLimitsNotice?`; `PanelView.limitsStrip` рисует блок через `PanelNotice` + кнопку `PanelButtonStyle` по образцу `hooksBlock`; текст пустой полосы зависит от состояния. Кнопка зовёт `PanelStore.signInClaude()` → `StatusController.signInClaude()` в `Actions.swift` → `runQuietCommand(.claudeLogin)`.
- **Команда `claude-login`** в `mcpbar.py`: `claude_login()` находит бинарь через `find_claude()`, пишет `ROOT/claude-login.command` (0700, атомарно) и зовёт `/usr/bin/open <файл>`. Почему `.command`, а не AppleScript: Terminal открывает такие файлы сам, без разрешения Automation и без Apple Events, которые приложение обещало использовать только для фокуса вкладки.
- **Знак в строке меню (R11)** — модель: `MenuBarAgent` получает поле `signedOut: Bool`, которое `MenuBarAgent.shown(...)` выставляет по `LimitsStatus.explainable`-правилу для провайдера Claude (`no-login`, опрос включён, цифры не свежее статуса); `IconRender.renderMenuBar` при `signedOut` рисует шкалы Claude с пониженной непрозрачностью и маленькую пометку (SF Symbol `person.crop.circle.badge.exclamationmark` или «!») в правом верхнем углу области шкал, не меняя ширину; `signature` иконки включает флаг, чтобы перерисовка шла только при смене состояния; tooltip и accessibility-описание — строки из модели. Почему модель: правило «когда показывать» уже есть у панели, второй копии быть не должно.
- **Уведомление** — в `StatePolling.tick()` после чтения состояния: `no-login` и ещё не уведомляли за этот запуск → `notify(title:body:)` (`Notifications.swift`), флаг `limitsNoticeSent` в `main.swift`.
- **Settings** — `SettingsStore` получает строку состояния опроса из того же `LimitsStatus.notice`, `SettingsView` показывает её под переключателем «Limits via Anthropic API».
- **Возраст Codex** — `merge_codex_limits` в `mcpbar_codex.py`: корневой `ts` = max по окнам пула `codex`, иначе max по всем. Per-window `ts` не меняется, поэтому решение «окно закончилось» в Swift (`NamedWindow.ended`) не зависит от корня.
- **Футер** — правило `LimitsNote.footer(groups: [(title, age)])` в `Sources/Model/LimitsNote.swift` вместе с `age(of:now:)`; `PanelData.panelLimitGroups` зовёт его.
- **Документы в том же изменении** (правило CONTRIBUTING): `CHANGELOG.md` секция `## [Unreleased]` (Added/Fixed), `PRIVACY.md` — новые файлы `limits-status.json` и `claude-login.command`, починка `statusLine` при запуске; `README.md`/`README.ru.md` — абзац про блок состояния и кнопку входа; `TROUBLESHOOTING.md` — «статусная строка пропала после обновления» и «No data — not signed in».
- **Версия не поднимается в этом прогоне**: релиз — публикация наружу, вопрос пользователю в отчёте.
