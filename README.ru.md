# Claude Control Bar

[English](README.md) | **Русский**

https://github.com/user-attachments/assets/39381f85-c8ce-4d32-8baa-dce67d39ee7e

Приложение для строки меню macOS, спутник **Claude Code**. Показывает, чем Claude занят, и даёт управлять сессиями, MCP-серверами и лимитами прямо из меню.

- **Сессии.** Анимированная иконка, пока Claude работает, жёлтая точка, когда он ждёт вашего разрешения, таймер хода и процент занятого контекста у каждой сессии. Клик по сессии поднимает терминал или редактор, где она запущена, — а с включённым **Exact terminal focus** ровно то окно и ту вкладку.
- **MCP.** У каждого сервера и каждого инструмента свой выключатель. Выключенный инструмент пропадает из контекста Claude при следующем старте сессии.
- **И Codex тоже.** Если вы работаете ещё и в **OpenAI Codex**, его сессии стоят в том же списке, что и сессии Claude: те же состояния, тот же таймер хода, та же заполненность контекста и та же янтарная точка «нужен ты». Его серверы MCP — в той же вкладке, с теми же переключателями. Клик по строке Codex ведёт туда, где сессию правда можно прочитать: десктопная открывает свой разговор по ссылке `codex://threads/`, терминальная поднимает свой терминал. Codex один раз спросит, доверяете ли вы хукам; пока не подтвердите, его сессии не видны — и панель говорит об этом, а не молчит: что именно покрывает это подтверждение, описано в разделе [Если вы работаете ещё и в Codex](#если-вы-работаете-ещё-и-в-codex). Всё читается из того, что Codex и так пишет на этой машине.
- **Лимиты.** Полоски 5-часового и 7-дневного лимитов прямо в строке меню, время сброса видно в самом меню. Если вы пользуетесь ещё и **OpenAI Codex**, рядом встают его собственные окна — они читаются из файла сессии, который Codex пишет сам, без токена и без запроса.

## Установка

### Плагином Claude Code (рекомендуется)

```bash
/plugin marketplace add InfinityScripter/claude-control-bar
```

```bash
/plugin install claude-control-bar
```

Приложение собирается из исходников на вашем Mac при следующем старте сессии, для этого нужны Xcode Command Line Tools (`xcode-select --install`). Обновляется вместе с плагином.

### DMG

1. Скачайте `claude-control-bar.dmg` из [последнего релиза](../../releases/latest).
2. Перетащите **Claude Control Bar** в «Программы».
3. Запустите один раз, чтобы установились хуки. Без активной сессии Claude оно может тут же закрыться — это нормально: хуки уже на месте.

> [!IMPORTANT]
> DMG не нотаризован, поэтому macOS заблокирует первый запуск. Откройте **Системные настройки → Конфиденциальность и безопасность** и нажмите **Всё равно открыть**. Или снимите карантин командой
> `xattr -dr com.apple.quarantine "/Applications/Claude Control Bar.app"`.

Ставьте что-то одно. Если установлены оба канала, каждый хук срабатывает дважды. Приложение умеет разруливать этот конфликт в пользу плагина, но держать оба всё равно незачем.

## Первый запуск

Приложение живёт в **строке меню**, в правом верхнем углу экрана, рядом с часами. Иконки в Доке у него нет, и собственного окна тоже — кроме окна настроек (⌘,): пока оно открыто, приложение видно в Доке как обычное, а после закрытия снова остаётся только иконка. Открывать его самому не нужно: оно запускается вместе с первой сессией Claude Code и закрывается, когда сессий не остаётся.

После установки:

1. **Запустите новую сессию Claude Code** — `claude` в терминале или Code-сессию в desktop-приложении. Сессии, открытые до установки, появятся только после своего следующего промпта или вызова инструмента.
2. **Канал плагина: дождитесь первой сборки.** На первом старте сессии приложение компилируется из исходников, это занимает от минуты до трёх; иконка появится, когда сборка закончится. Если она так и не появилась — загляните в `~/.claude/control-bar/problems.log`.
3. **Найдите краба в строке меню.** Без работающих сессий он спит; пока Claude работает — ходит, а жёлтая точка значит, что сессия ждёт вашего разрешения. Кликните по иконке — сессии, выключатели MCP и лимиты живут в этом меню; у настроек есть собственное окно.

Иконки нет?

- Приложение из DMG, открытое руками, **сразу закрывается, если нет активной сессии** — это задуманное поведение, а не краш. Запустите его один раз, чтобы установились хуки, затем запустите сессию.
- Самая частая причина — забитая строка меню: macOS прячет не поместившиеся элементы за шеврон `›`, и со стороны это неотличимо от «приложение не запустилось». Уберите пару иконок из строки меню (перетаскивание с зажатым Cmd), чтобы освободить место.
- `pgrep -x ClaudeControlBar` в терминале: число — приложение работает и спрятана только иконка; пустой вывод — оно не запущено: запустите сессию или смотрите [TROUBLESHOOTING.md](TROUBLESHOOTING.md).

### Если вы работаете ещё и в Codex

У Codex своя система хуков, и приложение пользуется ею так же, как хуками Claude Code. При установке оно дописывает восемь записей в `~/.codex/hooks.json`; ваши собственные хуки там не трогаются.

**Codex не запускает хук, которому не сказали доверять.** Подтвердите один раз — кнопкой **Approve** в панели или в **Settings → Codex**, кнопкой **Install hooks again** в **Settings → About** или на экране проверки в самом Codex, — и сессии Codex встанут в панель рядом с сессиями Claude. Приложение подтверждает только по вашему нажатию, никогда само при запуске, и только свои восемь записей: одобрение записывает Codex, с хешем, который считает сам, — ровно как сделал бы его экран проверки. Пока не подтвердили, Codex не записывает ни одной сессии вообще, и вкладка «Sessions» говорит именно это, а не выглядит так, будто Codex не запущен.

Десктопное приложение Codex показывает хуки в **Settings → Hooks** только для открытых в нём проектов, поэтому без открытого проекта там написано *No hooks found*, даже когда записи приложения в `~/.codex/hooks.json` на месте.

Подтверждение — это согласие на восемь shell-команд, поэтому вот что за ними стоит:

| | |
| --- | --- |
| **Какие скрипты** | `~/.claude/control-bar/update.js` на шести событиях (`UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PermissionRequest`, `Stop`, `Interrupt`) и `~/.claude/control-bar/lifecycle.js` на `SessionStart` и `SessionEnd`. Оба ставит это приложение, и это те же два файла, которые запускают хуки Claude Code. |
| **Что пишут** | По одному небольшому JSON на сессию в `~/.claude/control-bar/codex/state.d/` с правами `0600`: состояние, папка проекта, ветка, id хода, заполненность контекста, pid. Всё остальное, что они пишут, лежит там же — файл-маркер, который придерживает проверку «поднято ли приложение», и `problems.log`, когда запись не удалась. За пределы `~/.claude/control-bar/` ничего не выходит. |
| **Что читают** | Payload хука со stdin плюс первую строку и хвост rollout-файла самой сессии — первая строка называет поверхность, хвост несёт счётчик токенов, который сообщает Codex. |
| **Что запускают** | `git status --porcelain` в папке сессии ради счётчика незакоммиченных файлов, `pgrep` — проверить, поднято ли приложение, и `open -g -b …`, чтобы поднять его, если нет. |
| **Что отправляют** | Ничего. Хуки не делают ни одного сетевого запроса. |
| **Зависимости** | Никаких — только встроенные в Node `fs`/`os`/`path`/`child_process`, ни одного npm-пакета. |

В самой панели для этого момента есть две кнопки: **What gets approved** открывает `~/.codex/hooks.json` в Finder, чтобы прочитать настоящие записи до решения, а **Approve** просит Codex записать одобрение и спрашивает его заново. Если одобрять уже нечего, кнопка только спрашивает — так же проверяется одобрение, данное в самом Codex.

Дальше постоянный ответ живёт в **Settings → Codex**: *Hooks approved*, *N hooks not approved* или *not asked yet*, когда Codex не удалось спросить. Чтобы забрать доверие обратно, уберите записи приложения из `~/.codex/hooks.json` — или запустите скрипт удаления, он уберёт их сам, — и Codex спросит снова, если они когда-нибудь появятся опять.

## Как пользоваться

Сессии, лимиты и выключатели MCP живут в иконке в строке меню, настройки — в отдельном окне; запускается и закрывается приложение само, как описано выше.

### Маскот-краб

**Crab Walking** — анимация по умолчанию при новой установке. Маскот меняется в зависимости от числа сессий Claude Code, которые работают параллельно прямо сейчас. Считаются только сессии, где Claude думает или выполняет инструмент; просто открытые и бездействующие сессии не влияют.

| Работающих сессий | Что делает краб |
| ---: | --- |
| 0 | Спит |
| 1 | Отдыхает с сигарой |
| 2–3 | Ходит — спокойно при двух сессиях, в полный темп при трёх |
| 4–5 | Краснеет, качается и потеет |
| 6+ | У него загорается голова |

В этих превью используются те же runtime-кадры и тайминг, что и в приложении:

| 0 · Сон | 1 · Сигара | 2–3 · Ходьба |
| :---: | :---: | :---: |
| ![Анимация спящего краба](assets/crab-moods/sleeping.gif) | ![Анимация краба с сигарой](assets/crab-moods/cigar.gif) | ![Анимация идущего краба](assets/crab-moods/walking.gif) |
| 4–5 · Перегрев | 6+ · В огне | Нужно разрешение |
| ![Анимация перегревшегося краба](assets/crab-moods/overheated.gif) | ![Анимация краба в огне](assets/crab-moods/on-fire.gif) | ![Анимация краба в ожидании разрешения](assets/crab-moods/permission.gif) |

Когда сессии нужно разрешение, краб переключается на отдельную сцену ожидания: поднимает табличку со знаком вопроса, затем смотрит в экран. Рядом остаётся жёлтый предупреждающий кружок, а в строке состояния появляется короткая надпись `Needs you`. После ответа краб возвращается к состоянию для текущего числа работающих сессий.

Спрайт освещён сверху слева — светлая кромка сверху, тёмная снизу, — поэтому на размере строки меню он читается как объём, а не как наклейка; в режиме System это оттенённый монохромный силуэт. Внутри каждой полосы темп следует точному числу сессий: потеющий краб дышит чаще с пятой сессией, огонь мерцает быстрее с каждой следующей.

Выключатели серверов и инструментов действуют на новые сессии: Claude Code собирает список инструментов на старте, уже открытые сессии работают со старым набором.

### Питомцы в строках сессий

Иконка в строке меню говорит, насколько занято всё сразу. **Питомец** говорит то же самое про одну сессию: маленький анимированный персонаж в начале каждой строки в панели, играющий состояние именно этой сессии.

| Сессия | Что делает питомец |
| --- | --- |
| Отдыхает | Спит |
| Думает или выполняет инструмент | Работает |
| Ждёт вашего разрешения | Поднимает взгляд |

Выбрать — в **Settings → Appearance → Session rows**. Там показаны сами питомцы, а не список имён, и каждый шевелится: по названию вроде *Null Signal* невозможно понять, что появится рядом с вашими сессиями. Пункт **None** возвращает прежние кружок и спиннер.

Питомцы берутся из трёх мест, и имя достаётся тому, кто нашёлся раньше:

1. **Само приложение.** С ним едет один питомец — Clawd, тот самый краб из строки меню, собранный из тех же кадров, поэтому они физически не могут разойтись.
2. **`~/.codex/pets`.** Собственная папка питомцев Codex. Всё, что туда поставлено, появляется в списке — хоть из кодексовского `hatch-pet`, хоть из галерей сообщества ([awesome-codex-pets](https://github.com/BeiXiao/awesome-codex-pets), [petdex](https://petdex.dev)). Папка перечитывается при каждом открытии окна настроек, так что поставленный на ходу питомец не требует перезапуска.
3. **Десктопное приложение ChatGPT, если оно у вас есть.** Оно везёт питомцев Codex внутри себя, и они читаются прямо оттуда, где лежат: ничего не копируется, и ничего чужого не лежит в этом репозитории. Удалите то приложение — эти питомцы уйдут вместе с ним.

Свой делается в том же формате, что у Codex: прозрачный PNG или WebP, клетка 192 × 208, восемь колонок, по ряду на анимацию (покой, бег вправо, бег влево, приветствие, прыжок, ошибка, ожидание, работа, просмотр). Подходит любой из двух опубликованных размеров — 1536 × 1872 на девять рядов или 1536 × 2288 на одиннадцать. Положите его в `~/.codex/pets/<имя>/` рядом с `pet.json`, и он появится в списке. Лист любого другого размера пропускается сам по себе и не трогает остальных — именно это не даёт изменению чужого формата утащить за собой панель. Разобранный пример — `tools/pet-sheet`, он собирает лист этого приложения из кадров краба.

Анимация подчиняется настройке **Motion**, как и всё остальное в панели: *Off* или системный Reduce Motion оставляют питомца неподвижным, а не убирают его. Работает она только пока панель открыта.

### Настройки

**Settings…** в меню или ⌘, — окно с четырьмя страницами (интерфейс приложения на английском).

**General**

- **Timer in menu bar** — время текущего хода рядом с иконкой. В строках сессий таймер есть всегда.
- **Thinking words** — вместо «Thinking…» одно из слов-заставок самого Claude Code («Manifesting…»).
- **Limits via Anthropic API** — опрос, из которого берутся полоски 5-часового и 7-дневного лимитов; выключено — запроса нет вовсе (см. [PRIVACY.md](PRIVACY.md)).
- **Exact terminal focus** — выключено по умолчанию и единственный здесь переключатель, который стоит разрешения macOS. Выключено: клик по сессии поднимает её терминал, и macOS показывает то окно, которым вы пользовались последним. Включено: клик ведёт ровно в то окно и ту вкладку, где сессия запущена. macOS спросит один раз, на следующем клике, — а приложение объяснит, о чём именно спросит, до того. Только Terminal и iTerm: остальные терминалы не сообщают наружу, какая вкладка какая, поэтому у них поведение прежнее. Отказ заодно выключает настройку обратно, а забрать разрешение можно в любой момент в «Конфиденциальность и безопасность → Автоматизация».
- **Codex limits** — 5-часовое и недельное окна Codex в полоске лимитов; берутся из свежего файла в `~/.codex/sessions`. Никуда ничего не уходит, а цифра старше окна, которое она измеряет, не показывается вовсе — строка Codex исчезает, пока он снова не поработает. Когда обычный лимит кончился и Codex увёл работу на **резервную** модель, окно так и подписано — `RESERVE` вместо своей длины: с этого момента процент меряет резервный пул, а не тот лимит, за которым вы следили.
- **Codex MCP servers** — серверы MCP самого Codex во вкладке MCP, своими группами и с такими же переключателями. Имена инструментов Codex отдаёт, подняв каждый настроенный сервер, — ровно так он делает и сам; если какой-то сервер медленный, этот тумблер и надо выключить.
- **Anonymous usage ping** — раз в день: версия приложения, версия macOS, чип, канал установки и никакого идентификатора, чтобы проект мог посчитать, сколько копий в ходу. Выключено — запроса нет вовсе; `CONTROL_BAR_NO_ANALYTICS=1` в окружении делает то же самое. Точный состав — в [PRIVACY.md](PRIVACY.md).

**Appearance**

- **Animation** — Crab Walking (по умолчанию), Claude Spark или Claude Code, спиннер из терминальных глифов.
- **Color** — Orange или System: адаптивная чёрно-белая иконка.
- **Session rows** — какой питомец стоит в начале каждой строки сессии, или *None* для прежних кружка и спиннера. Подробнее — [Питомцы в строках сессий](#питомцы-в-строках-сессий).
- **Limits strip** — как полоска показывает двух провайдеров. *Two rows* (по умолчанию) ставит Claude и Codex в два ряда, у каждого своё имя и ближайший сброс. *Switcher* отдаёт всю ширину одному, второй уходит за вкладку — под именем вкладки остаётся волосяная полоска самого заполненного окна этого провайдера. С одним провайдером полоска в любом случае одна.

**Motion** — насколько подвижно само меню. *Off* останавливает всю анимацию; *Subtle* (по умолчанию) оживляет карточки, шкалы и переключатели; *Expressive* добавляет к этому появление строк лесенкой — тех, у которых есть собственная вьюха. Системный Reduce Motion действует поверх выбора: движение заменяется кроссфейдом, а не убирается совсем, чтобы смена состояния оставалась видимой.

**Sounds** — два события. *When a turn finishes*: выключено (по умолчанию), каждый ход или только ходы длиннее 1, 5 или 15 минут. *When Claude needs you*: короткий системный звук macOS в момент, когда сессия начинает ждать вашего разрешения — по умолчанию Tink, на выбор Purr, Ping, Glass, Hero, Submarine; выбор пункта сразу его проигрывает. Звука нет, если терминал или приложение с этой сессией и так на переднем плане: запрос уже на экране, слышать о нём незачем.

**Check MCP now** (⌘R) и **Open settings.json** остались в меню, а не переехали сюда — это действия, а не настройки. Каждый выключатель сервера и инструмента пишется в `~/.claude/settings.json`.

Ещё приложение показывает уведомление macOS, когда MCP-сервер упал или вернулся. Если уведомления запрещены, в меню появляется строка *Notifications are off*, которая открывает нужный раздел Системных настроек.

### Слэш-команды

Плагин добавляет в Claude Code две команды:

- `/mcp-health` — карта MCP текстом: какие серверы ответили, сколько у каждого инструментов, что выключено, плюс окно контекста каждой открытой сессии и лимиты.
- `/limits-capture install|uninstall|status` — необязательный второй источник для полосок лимитов. Оборачивает вашу команду `statusLine`, и цифры обновляются из данных, которые Claude Code ей передаёт, — свежее, чем опрос API, пока активна сессия в терминале; `uninstall` возвращает прежнюю команду в точности.

Настройки раскладки, ключи `defaults write` и диагностические режимы перечислены в [TROUBLESHOOTING.md](TROUBLESHOOTING.md#knobs-and-diagnostics).

Цифры лимитов Claude приложение берёт с той же ручки Anthropic, что и команда `/usage`. Для запроса используется OAuth-токен из Keychain, который туда положил сам Claude Code. Уходит он только на `api.anthropic.com`, а опрос можно выключить в Settings → General. Цифры Codex — локальные: Codex сам записывает остаток своих лимитов в файл сессии в `~/.codex/sessions`, приложение читает свежий из них, и никакого запроса при этом не делается. Полный список файлов, которые приложение пишет, и запросов, которые оно делает, лежит в [PRIVACY.md](PRIVACY.md).

## Требования

- macOS 13+
- [Claude Code](https://claude.com/claude-code) (CLI или Desktop-приложение)
- Node.js и системный `/usr/bin/python3`
- Xcode Command Line Tools нужны только плагину (он собирает приложение локально), для DMG не нужны

## Удаление

Если ставили плагином: `/plugin uninstall claude-control-bar`, потом перетащите `~/Applications/Claude Control Bar.app` в Корзину.

Если ставили из DMG:

```bash
node "/Applications/Claude Control Bar.app/Contents/Resources/uninstall.js"
```

Скрипт убирает хуки, дальше перетащите приложение в Корзину. Служебные файлы лежат в `~/.claude/control-bar/`.
